# Security policy

Nox runs on a user's own desktop with microphone, screen and file access, so security reports are
treated as the highest-priority class of issue in this project.

## Supported versions

Nox is pre-1.0. Only the latest release and the current `main` branch receive security fixes;
older tags do not.

| Version            | Supported |
| ------------------ | --------- |
| `main` (unreleased)| Yes       |
| Latest release     | Yes       |
| Anything older     | No        |

## Reporting a vulnerability

**Do not open a public issue for a security problem.**

Use GitHub's private vulnerability reporting: go to the repository's **Security** tab →
**Report a vulnerability**. That creates a private advisory visible only to you and the
maintainers. If private reporting is unavailable to you for any reason, open a public issue that
says only "security report, please enable a private channel" — with no details — and wait for a
maintainer to contact you.

Please include, as far as you can:

- what an attacker can do (impact), not only what is wrong;
- the version or commit, and your Windows/Python/Node versions;
- reproduction steps or a proof of concept;
- whether you believe it is already exploited in the wild.

## What happens next

| Step                                    | Target                          |
| --------------------------------------- | ------------------------------- |
| Acknowledgement of your report           | 7 days                          |
| Initial assessment (severity, validity)  | 14 days                         |
| Fix or a written mitigation plan         | 90 days from the report         |
| Public disclosure                        | after the fix, or at 90 days    |

This is a solo/small-project effort with no paid support tier, so these are honest targets rather
than a contractual SLA. Coordinated disclosure: we ask you to keep the report private until a fix
ships or 90 days have passed, whichever comes first. We will credit you in the advisory unless you
ask us not to.

## Scope

In scope: anything that breaks one of Nox's stated guarantees — the kill switch, privacy modes and
zones, the permission engine, the egress guard, the audit chain, IPC authentication, secret
handling, plugin sandboxing, and the Rocket League observation-only boundary. See
[`docs/SECURITY.md`](docs/SECURITY.md) for what those guarantees are and
[`docs/PRIVACY.md`](docs/PRIVACY.md) for the privacy claims a report can be measured against.

Out of scope: findings that require an attacker who already has administrator rights or code
execution on the machine, vulnerabilities in third-party dependencies with no Nox-specific
exploitation path (report those upstream; we track dependency updates via Dependabot), and reports
generated by automated scanners without a demonstrated impact.

## Safe harbour

Research carried out in good faith against your own installation, without accessing other people's
data, without degrading anyone else's service, and reported through the channel above, will not be
met with legal action from this project.
